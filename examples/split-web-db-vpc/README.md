# Example: split web + DB over the VPC (production, one region)

Made up: web droplet `web-01` (`10.0.0.6`) on Ploi, DB droplet `db-01` (`10.0.0.5`), both in `nyc3`,
VPC `10.0.0.0/20`. Postgres and PgBouncer listen on the private IP only; ufw allows the VPC range only.

**Why:** the DB never has a public port, the web node can be rebuilt without touching data, and each droplet
is sized for one job. `production-single` adds PITR, off-site backups, TLS, alerts and `STRICT=1`.

```bash
examples/run.sh split-web-db-vpc            # validate (offline): RAM per node, TLS, alerts, ranges
bin/siwo configure --profile production-single --client <you> --set APP=shop \
  --set ALERT_EMAIL=<you@example.com> --set DB_PRIVATE_IP=10.0.0.5 --set WEB_PRIVATE_IP=10.0.0.6 --set VPC_CIDR=10.0.0.0/20
```

Then follow the printed `next:` steps and the [new server](../../docs/checklists/01-new-server.md),
[DB](../../docs/checklists/02-db-setup.md) and [web](../../docs/checklists/03-web-setup.md) checklists.

Checklist:

- [ ] Both droplets in the same region and VPC (`bin/siwo web check-db-reach --remote web-01 10.0.0.5 6432`)
- [ ] App `.env` written with `bin/siwo env init --env prd` (password generated by the DB manager, never typed)
- [ ] PITR restore drill done once ([monthly restore drill](../../docs/checklists/monthly-restore-drill.md))

Lesson: a DB bound to `0.0.0.0` "just for a minute" is how databases get found by scanners. The manager refuses it.
