# Repository structure

`vps-server-workbench` holds the tools for building and running VPS servers (DigitalOcean + Ploi today):
shell scripts that run on or against servers, Docker stacks, and PHP and Python packages for automation
that grows beyond shell. Folders are split **by language first, then by area**, so each language keeps its
own tooling (shellcheck, Composer, pyproject) and each area is easy to find.

```text
bin/          entry points: vsw (dispatcher for every tool)
shell/        Bash tools, one folder per area
  db/           DB server: docker-db-server-manager.sh (runs on the server), remote-run.sh (workstation)
  web/          web server: update-env-db.sh, check-db-reach.sh
  deploy/       ploi-deploy.sh (pasted into Ploi)
  tunnels/      workstation SSH tunnels: db-tunnel.sh
php/          Composer package simtabi/vps-server-workbench (PSR-4, namespace Simtabi\VpsServerWorkbench)
  bin/ src/ tests/
python/       Python package vps-server-workbench (pyproject, src layout, import vps_server_workbench)
  src/ tests/
stacks/       Docker Compose stacks deployed to servers: caddy/ (the DB stack is generated by the manager)
config/       *.example templates for every tool (no secrets, ever)
docs/         README (index), structure.md (this page)
  guides/       how-to: getting started, SSH, web servers, deploy, daemons, connections, upgrading, troubleshooting
  reference/    facts: architecture, DB manager reference, security, status
  runbooks/     step-by-step procedures for live servers (rollout plan)
examples/     per-project configs (the only place a project name may appear)
tools/        standalone helpers that are not part of a server workflow (ploi-do-plan-finder)
tests/        repo-level tests: shell/ (smoke, deploy sandbox, upgrade integration), docs/ (links, Mermaid)
scripts/      compatibility shims for the old paths (see below); do not add new files here
```

The layout follows common conventions: `bin/` for executables, Composer's PSR-4 `src/` + `tests/`, the
PyPA-recommended `src/` layout (tests run against the package, not the folder), and docs split into
guides, reference and runbooks (the [Diátaxis](https://diataxis.fr) idea: how-to vs facts vs procedures).
Diagrams stay inline as Mermaid in the page they explain; `make mermaid` renders them all.

## Where new things go

| You are adding | Put it in | Name it | Wire it into |
|---|---|---|---|
| a Bash tool | `shell/<area>/` (new area folder if none fits, e.g. `shell/ssh/`) | `kebab-case.sh`, executable, header with usage | nothing: `make lint` finds every `*.sh`; add smoke checks in `tests/shell/smoke.sh`; `bin/vsw <area> <tool>` finds it |
| PHP automation | `php/src/<Area>/` class + a command in `php/bin/vsw-php` | `PascalCase.php`, one class per file | a test in `php/tests/` (`make php-test`) |
| Python automation | `python/src/vps_server_workbench/` module + a subcommand in `cli.py` | `snake_case.py` | a `test_*.py` in `python/tests/` (`make py-test`) |
| a Docker stack | `stacks/<name>/` with `docker-compose.yml`, `.env.example` | lower-case folder | `make compose-check` |
| a config template | `config/<tool>.env.example` | `<tool>.env.example` | the tool's docs |
| a guide / runbook | `docs/guides/` or `docs/runbooks/` | `kebab-case.md` | the table in [docs/README.md](README.md); `make links` checks it |
| a project's values | `examples/<project>/` | as the tool expects | the project README |

Rules that do not change: no secrets in the repo, no project names outside `examples/` and `CHANGELOG.md`
(`make test` enforces it), pinned image versions, and `make ci` green before every commit.

## Old to new paths

The 2026-10 reorganisation moved files without changing what they do. Servers are not affected: the manager
is still installed as `/root/docker-db-server-manager.sh` with its config at `/etc/docker-db-server-manager.conf`.

| Old path | New path | Shim at the old path? |
|---|---|---|
| `scripts/db/docker-db-server-manager.sh` | `shell/db/docker-db-server-manager.sh` | yes (local runs only; `bash -s <` piping needs the new path) |
| `scripts/db/remote-run.sh` | `shell/db/remote-run.sh` | yes |
| `scripts/web/update-env-db.sh` | `shell/web/update-env-db.sh` | yes |
| `scripts/web/check-db-reach.sh` | `shell/web/check-db-reach.sh` | yes |
| `scripts/local/db-tunnel.sh` | `shell/tunnels/db-tunnel.sh` | yes |
| `scripts/deploy/ploi-deploy.sh` | `shell/deploy/ploi-deploy.sh` | no (pasted into Ploi; re-paste from the new path) |
| `compose/caddy/` | `stacks/caddy/` | no |
| `tests/smoke.sh`, `tests/deploy-sandbox.sh`, `tests/upgrade-it.sh` | `tests/shell/…` | no (use `make test` / `make it`) |
| `tests/check-links.py`, `tests/render-mermaid.sh` | `tests/docs/…` | no (use `make links` / `make mermaid`) |
| `docs/{getting-started,ssh-access,web-server-ploi,web-server-caddy,deploy,daemons,connections,upgrading,troubleshooting}.md` | `docs/guides/…` | no |
| `docs/{architecture,db-server,security,status}.md` | `docs/reference/…` | no |
